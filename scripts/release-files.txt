# Allowlist of scripts/ paths that ship inside the release tarball.
#
# Consumed by build-release.sh as `rsync --files-from`, relative to scripts/.
# This REPLACED a deny-list in .buildignore, which failed OPEN: any new dev
# script silently shipped unless someone remembered to exclude it. That bit us
# twice: build-releases-manifest.js, check-db-ownership.js, lint-release-notes.sh
# and refresh-ntp-defaults.js were all shipping to production appliances with no
# runtime purpose, and a newly added build guard (check-install-scripts.js) would
# have joined them. An allowlist fails CLOSED: forget an entry and the build
# stops, which is the direction you want to be wrong in.
#
# Rules:
#   - Only add something an OPERATOR or the appliance itself needs at runtime
#     (install, update, rollback, systemd/polkit/sudoers integration, signature
#     verification). Build/dev tooling belongs OUT.
#   - build-release.sh verifies every path here exists before staging, so a
#     rename or deletion fails the build instead of silently dropping a file.
#   - Blank lines and #-comments are stripped before rsync sees this.
